# m+m 8D Reporting User Guide

## Introduction

This module extends the processing of sales complaints in Microsoft Dynamics 365 Business Central with a controlled 8D process. You maintain the required setup, define complaint profiles and assignments, and then process the complaint directly in the Sales Return Order through to printing, sending, and follow-up of the 8D report.

The application is intended for key users in quality assurance, sales, complaint processing, and adjacent departments. The typical flow is:

1. Maintain setup and master data.
2. Define complaint profiles and profile assignments.
3. Record and release the Sales Return Order.
4. Process 8D-relevant lines, documentation, attachments, and costs.
5. Print the 8D report or queue it for sending.
6. Follow up on sending, logs, and history.

## Quick Start for Users

### The Complaint Process in Brief

1. Use **Search** to open the **Complaint Setup** page and check number series, report and email defaults, and inventory parameters.
2. Then maintain the master data on the **Complaint Discipline**, **Complaint Team**, **Complaint Error**, **Corrective Actions**, **Complaint Documentation Type**, **Type of Compl. Costs**, **Reject Reasons**, and **Return Reason Detail** pages.
3. Under **Complaint Profiles**, create at least one profile and use the **Change Status** action to set the status to **Certified**; only certified profiles are pulled during release.
4. Under **Profile Assignments**, define which profile applies to which customers, items, or production references.
5. Open a **Sales Return Order** and complete the 8D fields in the header and lines.
6. Release the document using **Release** so that the return order complaint profile is pulled per item line.
7. Record complaint documentation, attachments, and complaint costs if needed.
8. Print the 8D report using the **Print 8D-Report** action, or monitor sending using **8D-Reports To Be Send**, the **Complaint 8D-Report-Log**, and the **Document History**.

## Setup

### Complaint Setup

The **Complaint Setup** page controls which number series, posting accounts, locations, and output definitions the module uses. Open the page first and maintain all required fields before users start working with complaints. The fields are organized into the **General** and **Complaint Email** FastTabs.

**General FastTab**

| Setup | Explanation |
| --- | --- |

| G/L Acc. No. Transport | If you enter a G/L account here, transport-related complaint costs are posted to this account; otherwise the account assignment for transport costs is missing. |
| Profile No. Series | If a number series is entered, each newly created complaint profile automatically receives a number from this series. |
| Return Order Complaint Profile No. Series | Determines the number series from which the return order complaint profiles pulled per complaint line receive their number. |
| Customer Complaint Profile No. Series | Determines the number series for customer-related complaint profiles. |
| Attachment No. Series | Determines the number series used when recording attachments. |
| Block Inventory | When this switch is set, the module blocks the affected inventory and uses the blocked-location and journal fields below for this purpose; otherwise no automatic inventory blocking takes place. |
| Item Ledger Entry Comment | If a text is entered, it is carried as a comment in the item ledger entries when inventory is blocked. |
| Blocked Location Code | Defines the location to which blocked goods are transferred. |
| Blocked Bin Code | Defines the bin within the blocked location to which blocked goods are posted. |
| Block Item Journal Templ. | Determines the item reclassification journal template through which blocking postings run; only a template of type Transfer using the **Item Reclassification Journals** page is allowed. |
| Block Item Journal Batch | Determines the journal batch name within the blocking journal template. |
| Standard 8D-Report-ID | Defines the report that is printed when no different report is entered on the customer. |

| Compl. Corr. Doc. Type | Defines the documentation type used to automatically create documentation lines for corrective actions. |
| Type of Compl. Cost Trsp. | Determines the cost type used for transport costs. |
| Consider Transp. Order Costs | When the switch is set, costs from the transport order flow into the complaint costs. |

**Complaint Email FastTab**

| Setup | Explanation |
| --- | --- |
| Complaint Document Name For Email | Defines the document name used for the 8D document when sending by email. |
| Complaint Message Atachament Name | Defines the name under which the message attachment appears in the email. |
| Default Complain Email Report | Defines the report used when sending the complaint email. |
| Report Interval | Determines the initial value for the report interval that new complaint profiles receive when created. |

### Setup Steps in a Sensible Order

1. Activate the module via **m+m Complain Active**.
2. Maintain all required number series.
3. Enter account and cost defaults.
4. Add the blocked location, blocked bin, and journal data if you manage blocked inventory.
5. Enter default values for printing and email.
6. Finally, check the report interval and the documentation type for corrective actions.

## Profiles and Assignments

### Complaint Profiles

With **Complaint Profiles**, you define the 8D structure that is later used in complaints. A profile consists of the complaint profile header and the assigned complaint profile lines. Use the **Change Status** action to move through the status values; use **Copy Profile** to create a new complaint profile or a new customer complaint profile as a copy.

**Complaint Profile Header**

| Field | Explanation |
| --- | --- |
| No. | Sequential number of the complaint profile from the configured number series. |
| Description | Business name of the profile. |
| Type | 8D stage of the profile (1D through 8D); at the same time limits the number of permitted discipline lines. |
| Status | Controls the usability of the profile and is advanced exclusively via the **Change Status** action. The values mean: **New** – the profile is in progress and can be changed or deleted; **Certified** – the profile is usable and is pulled during release, lines are no longer editable; **Under Development** – the profile is again in progress and editable; **Closed** – the profile is completed and no longer used. |
| Report Interval | Determines the interval at which an 8D report becomes due for uses of this profile. |
| Qty. Assigned Customer | Shows how often the profile is already used through an assignment. |

**Complaint Profile Line**

| Field | Explanation |
| --- | --- |

| No. | Contains, depending on the sales type, the customer number or the group key. |

## Daily Work in the Sales Return Order

### Starting from the Sales Return Order

The actual processing takes place in the **Sales Return Order**. The user creates the document, transfers the document lines to be complained about, and then completes the 8D information in the header and lines.

The extension adds the **8D** FastTab with additional fields to the document header and extends the lines with complaint and documentation references. After release, the matching return order complaint profile is pulled from the assignments for each item line without an existing profile.

### 8D Fields in the Document Header

| Field | Explanation |
| --- | --- |
| Vendor No. | Specifies the vendor used for a return transport; only vendors marked as a carrier are available for selection. |
| Transport Order No. | Shows the purchase order number linked via the **Create Transport Order** action. The field is read-only. |
| Total Complaint Costs | Sums the complaint costs recorded for the complaint. |
| Return Order Period | If you enter a date formula here, the module calculates the return order due date from it based on the document date. |
| Return Order Due Date | Shows the planned closing date of the complaint calculated from the closing period. |
| Complaint Status | Controls the processing state of the complaint; a change is confirmed and checked against the team permissions. The values mean: **Open** – complaint newly recorded; **In Process** – processing in progress; **Rejected** – complaint rejected; **Rejection Request** – rejection requested; **Approved** – complaint released; **Good Will Approved** – good will granted; **Good Will Request** – good will requested; **Error** – faulty state. |

The document header also provides the actions **Create Transport Order** (creates a purchase order as a return transport), **Send Complaint Email** (sends the 8D report by email; also available as a ribbon action), and **Document History** (opens the document history for the document).

### 8D Fields in the Complaint Lines

| Field | Explanation |
| --- | --- |
| Return Reason Detail Code | Details the return reason at line level. |
| Rejection Reason Code | Documents a reject reason on the line. |
| Return Order Complaint Profile No. | References the return order complaint profile pulled for the line. |
| Attachments | Shows the number of stored attachments and serves as the entry point into attachment maintenance. |
| Total Complaint Costs | Shows the complaint costs recorded for the line. |

In the line menu **Line > 8D**, the actions **Complaint Cost** (only for lines of type Item; opens the cost lines) and **Print 8D-Report** (prints the 8D report for the selected lines) are available.

### Processing Order in Day-to-Day Business

1. Create the Sales Return Order and transfer the original document lines.
2. Complete the 8D header data.
3. Maintain line-related return and rejection information.
4. Release the document using **Release** so that the profile is pulled from the assignment.
5. Work through the individual disciplines in the return order complaint profile.
6. Add documentation lines, attachments, and costs to individual disciplines.
7. Only then trigger report printing or sending.

## 8D Report and Email

### Printing the 8D Report

The 8D report (**Complaint 8D-Report**) is used from the Sales Return Order via the line action **Print 8D-Report**. The following data in particular is relevant for the printout:

1. the return order complaint profile with its disciplines,
2. documentation lines marked via **Print Line on 8D-Report**,
3. attachments and the document names entered in the setup,
4. report intervals and sending history.

Therefore, always maintain the profile, discipline status, and documentation flags completely before printing. Each printout is logged in the **Complaint 8D-Report-Log**.

### Email Preparation

For email output via **Send Complaint Email**, the module uses the names entered in the setup and the Default Complain Email Report. A prerequisite is at least one matching complaint text for the customer, document type, and language code. Check beforehand:

1. Complaint Document Name For Email and Complaint Message Atachament Name in the setup,
2. complete documentation lines,
3. the print-relevant marking of the lines,
4. the due report interval.

## Inventory, Blocked Stock, and Follow-up Documents

If you activate **Block Inventory** in the setup, the module works with a blocked location, a blocked bin, and a defined item reclassification journal template. In this case, proceed as follows:

1. Maintain **Blocked Location Code** and **Blocked Bin Code** in the setup.
2. Add **Block Item Journal Templ.** and **Block Item Journal Batch** for blocking postings.
3. Record the complaint completely before triggering inventory movements or follow-up documents.
4. Check **Transport Order No.** and transport costs if return transports or follow-up documents arise.

The module also adds references to item ledger entries (page **Item Ledger Entries**) and document histories. This allows the user to trace which inventory or document movements belong to the complaint.

## Typical Use Cases

### Customer Reports a Faulty Delivery by Email

**Trigger**
A customer reports a faulty delivery by email and expects a structured response.

**Starting Point in BC**
The user uses **Search** to open the **Sales Return Order** and creates a new document.

**Core Flow**
1. Transfer the affected document line.
2. Complete the 8D fields in the header, in particular Complaint Status, Return Order Period, and, if applicable, the vendor for the return transport.
3. Maintain the line fields for Return Reason Detail Code and profile reference. (Prerequisite: a matching profile assignment; see **Profiles and Assignments**.)
4. Release the document using **Release** so that the matching return order complaint profile is pulled per line.
5. In the return order complaint profile, add the responsible teams and processors.
6. Use the **Complaint Documentation** action to record the first problem description and mark it via **Print Line on 8D-Report**.
7. Store attachments from the email in **Complaint Attachments**.

**Completion**
Use **Print 8D-Report** to print the report, or monitor further sending via **8D-Reports To Be Send**.

### Internal Quality Notification Leads to 8D Processing

**Trigger**
Quality assurance identifies an error internally that must be processed systematically.

**Starting Point in BC**
The user first checks **Complaint Profiles** and then opens the **Sales Return Order**.

**Core Flow**
1. Check whether a suitable profile with status **Certified** exists.
2. If necessary, create a profile, certify it via **Change Status**, and add a profile assignment.
3. Create a complaint or open an existing document and release it.
4. Work through the profile lines and maintain the team, team member, and comment for each discipline.
5. Reconcile errors and corrective actions via the associated master data.
6. Record actions and results in the complaint documentation.

**Completion**
After complete processing, print the report and trace the process via the **Complaint 8D-Report-Log** and **Document History**.

### Return Transport and Costs Are to Be Documented

**Trigger**
Return transport and additional costs arise for the complaint.

**Starting Point in BC**
The user opens the affected **Sales Return Order**.

**Core Flow**
1. Enter the vendor for the return transport in the **Vendor No.** field.
2. Use **Create Transport Order** to create a return transport and check **Transport Order No.**
3. Use the line action **Complaint Cost** to record costs.
4. For each cost line, check Type of Compl. Cost, Amount, and **Copy to Purch. Ret. Order**.
5. With active inventory blocking, additionally observe the inventory parameters from the setup.

**Completion**
Check **Total Complaint Costs** in the document header and then continue with report printing or send preparation.

## FAQ and Troubleshooting

### 1. Why is no return order complaint profile pulled after release?
First check whether **m+m Complain Active** is set in the setup, and check the **Profile Assignments**. Without a matching assignment by customer, item, source, or production reference, the complaint cannot pull a profile and release is aborted with a message.

### 2. Why can a profile not be used in production?
Check the **Status** of the complaint profile. Only profiles with status **Certified** are pulled; a profile in **New**, **Under Development**, or **Closed** is not available for operational processing. Advance the status via the **Change Status** action.

### 3. Why does a discipline appear in the wrong processing step?
Check the **Order No. in Complaint** in the profile. This number controls the processing order.

### 4. Why does a documentation line not appear on the 8D report?
In **Complaint Documentation**, the **Print Line on 8D-Report** option must be set.

### 5. Why is no file expected for the attachment?
Check the **Type** in **Complaint Attachments**. With **Hyperlink**, only a reference is expected; with **Database**, a stored file attachment.

### 6. Why are complaint costs missing from the total?
Record the costs completely via **Complaint Cost** and check whether the lines are assigned to the correct Return Order No. and Return Order Line No.; the header total field **Total Complaint Costs** only sums correctly assigned lines.

### 7. Why is no sending or follow-up date shown?
Check the setup and report interval, as well as the entries in **8D-Reports To Be Send** and in the **Complaint 8D-Report-Log**. The list only shows lines with a return order complaint profile whose due date falls within the period defined via **Ret. Ord. Show Days To Due Day**.

### 8. Why can a team member not perform a status change?
In **Complaint Team Member**, check whether the member is a **Team Leader** or has the required **Approval Authorisation**, **Rejection Authorisation**, or **Good Will Authorisation**. The status change of the complaint compares the logged-in user with the members of the responsible team.

### 9. Why is inventory blocking incompletely prepared?
In the **Complaint Setup**, check the fields **Blocked Location Code**, **Blocked Bin Code**, **Block Item Journal Templ.**, and **Block Item Journal Batch**. The journal template must be of type Transfer and use the **Item Reclassification Journals** page.

### 10. Why is the history of a follow-up document not traceable?
Open the **Document History**. There, source and target references must be present for follow-up; use **Show Document** to jump to the referenced document.
